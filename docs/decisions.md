# Decisions and open questions

Log of choices made while starting the project (2026-10-29). Each one can be changed. Items marked **Needs you** are blocked on something only you can provide.

## Choices made

1. **Python 3.11+, standard library only.** No third-party runtime or test dependencies. Easier to run locally, and nothing to audit. Tests use `unittest`, which pytest also runs.
2. **One SQLite file for the HTTP cache and the graph** (`data/liner.sqlite`, gitignored). Caching by full URL means every crawl can be resumed without network traffic.
3. **MusicBrainz web service first, bulk dumps later.** The API is slow: about one recording per second on a first crawl. The JSON dumps (CC0 core data, including credits) are the route to larger subsets. Not built yet.
4. **Graph model.** Artist and recording nodes, with credit edges that carry a role and an optional detail (for example an instrument). Direct artist-to-artist links (such as "member of band") are kept separately. Shared recordings are counted at query time, not stored.
5. **Ranking is a count for now.** Weighted scoring belongs to Phase 3, and it will be written so that each weight can be read and changed.
6. **Sampling.** A crawl reads the first recordings MusicBrainz lists, up to `--max-recordings` (default 50). That is a biased sample, and the code says so.
7. **Retries.** 429 and 503 responses are retried with 1, 2 and 4 second waits. Other errors (including 404) fail at once, so a missing artist does not silently produce an empty graph.
8. **Supplementary MusicBrainz data is not redistributed.** Tags and genres are CC BY-NC-SA. The repo ships no snapshot of them, and any future genre features will fetch them at runtime.
9. **Name.** The project is called **Liner**. You confirmed the name on 2026-10-29.
10. **Git.** The folder is a local git repo (`main`), with no commits and no remote. Commits and the GitHub repo come later, once you approve them.
11. **WSL2 not installed.** `wsl --status` reports it is not installed. The current stack runs natively on Windows (Python 3.13, Git 2.55), so I did not install it. Installing WSL needs admin rights and a reboot. Revisit it only if audio tools need Linux.
12. **Logo.** Stacked waveform traces: fifteen layers of one tone, each shifted in time, with hidden-line occlusion. The tone changes across the mark, from a pure sine on the left to the full tone on the right, so the stack moves from familiar to complex. The front layers swing wider than the back (perspective). The arc that joined two crests of the back trace was removed at your request, so the published mark is monochrome. The geometry is generated by `assets/logo/stacked_waveforms.py`, so it can be reproduced exactly. Alternatives stay in the generator: the earlier 13-layer stack (`stack-13`), the same stack without the morph (`depth-15-bridge`), the morph with the amber arc (`morph-15-bridge`), a 21-layer version, and a 9-layer version with an amber front trace. Earlier marks were replaced: an L made of nodes, a coloured version with a trail, two beamed notes, a waveform with a bridge arc (too simple), a record with a needle (read as generic), and a stack change too small to notice. Delivered as an SVG mark, light and dark lockups, and a 512 px PNG of the mark (`assets/logo/`).
13. **Scoring factors and weights.** Five factors: credits, path, link, era and familiarity. Starting weights are 1.0, 0.6, 0.8, 0.4 and 0 (familiarity off). These are my judgement calls, not measured values. The evaluation should tune them.
14. **Hub discount.** A shared recording counts for less the more artists are credited on it. Credit overlap is also normalised by how many recordings each artist has. The path factor is a random walk with restart at 0.15, and its scores are divided by the square root of each candidate's recording count.
15. **Diverse selection.** Maximal marginal relevance with lambda 0.7, applied to the top 100 candidates.
16. **Feedback is a fixed-step nudge, not learning.** Each like or skip moves each contributing factor by 0.1 times its share of the evidence, within bounds of 0 and 2. Weights persist in the profile, and reset restores the defaults. Per-session weights wait for the radio.
17. **Evaluation uses a hand-built seeds file.** Metrics are precision and recall at k, coverage, similarity between suggestions, the share with reasons, and a split by how documented each seed is. The file holds the judgement; the code only measures against it.
